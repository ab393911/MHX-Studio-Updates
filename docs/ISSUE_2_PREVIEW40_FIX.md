## 诊断与修改

- 绑定键原来已是十进制雷电编号，JSON 保存/重读机制在自动测试中正常；没有证据证明用户本机发生过写入失败。Issue 中编号 2～5 逐台首次确认，与原代码“不跨实例复用已确认组件”相符，不能说已查明用户全部重复确认的唯一原因。
- 新实例缺少绑定时，仅在已有唯一人工确认的游戏组件时，借用组件作为候选；在目标实例重新核验身份及完整 package/activity 安装入口后，保存目标自己的 Android ID 和编号键。不同组件冲突、目标已有绑定但身份变化、入口不存在均不静默覆盖。软件重启继续读取每台独立绑定。
- 首次/重新人工确认须核验游戏当前前台。安卓系统桌面、launcher 和系统组件不能成为游戏绑定，也不再自动选中桌面。已有错误桌面绑定会被启动校验拒绝，可通过“发现/绑定游戏”明确纠正；不清空原配置。
- 手工确认与复用共用事务式保存，写入失败回滚内存绑定。配置未知字段、职业和角色设置保留。
- 对明确的 offline、设备丢失等传输错误，身份验证最多尝试 3 次，间隔 500ms，总期限 55s；只定向 reconnect 当前 serial，不 kill-server、不重启模拟器、不重放点击或启动命令。成功恢复后重读编号侧与 serial 侧的 Android/boot 身份；身份不符立即停止。普通成功检查不额外增加编号侧查询，保持正常路径的命令量。
- 识别厂商控制台“退出码为 0、stdout 却报告 offline”的情况。未取得身份/扫描中不直接等同于明确 offline；明确 offline 在实例状态中单独标示。
- 点击游戏启动时，如果列表缓存中设备仍未核验，按需做最多 3 轮新列表和完整身份映射，再允许继续；不根据旧 serial 或端口公式猜编号。选中实例已改变时不继续原动作。
- 故障开始、恢复时间及原因写入 `diagnostics/adb-connections.log`，界面保留最近日志。恢复后必须重新核验，不能因为上一轮曾在线就点击。

## 调度核对

`SetTimer(..., 1200, ...)` 仍是消息循环的界面/调度检查。
实际扫描仍受 `nextScan`、busy、标定/选择窗口及关闭状态约束。
完成扫描后才再等待 12 秒；单轮扫描可能更长，1.2 秒定时器不意味着每 1.2 秒执行 ADB 扫描。中间列表明确标为“扫描中/身份待核验”，完整结果显示扫描完成时间。没有提高周期扫描频率。
