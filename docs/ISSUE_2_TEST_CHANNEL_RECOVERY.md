## 加入通道与升级

首次在 preview.40 软件界面的“更新清单”填写：
https://raw.githubusercontent.com/ab393911/MHX-Studio-Updates/updates/issue2-test.json

点“保存设置”，再点“一键检查更新”。以后只需点“一键检查更新”。无需下载 ZIP、手工替换 EXE、运行 CMD/BAT 或安装 Python。

请先停止正在执行的操作。升级保留原数据目录，下载与 SHA-256 校验完成后，旧进程退出，独立旧助手备份原 EXE、配置、SQLite/WAL/SHM并替换，随后重启、检查 GUI 健康；启动失败使用现有回滚机制。原有自动计划仍保留，本次验收请在软件中暂停业务自动执行，不清空配置。

## 升级前记下安装位置

若不知道 EXE 的位置，可在 Windows 任务管理器中找到正在运行的 MHXStudio，右键“打开文件所在的位置”，保留该资源管理器窗口。此操作不修改文件。

每次更新的文件可在该安装目录定位：

- 事务与恢复助手：`.mhx-updates\tx-随机编号\plan.json`、`updater.exe`、`result.json`。
- 旧 EXE：`.mhx-backups\tx-随机编号-MHXStudio.exe`（若原 EXE 名称不同，以 plan.json 的 Backup 路径为准）。
- 配置/数据库快照：`.mhx-backups\tx-随机编号-config\manifest.json` 及其文件。
- 原数据目录以软件日志“配置位置”或 plan.json 的 DataRoot 为准，通常为 `%LOCALAPPDATA%\MHXStudioNext`。

不要删除、改名或编辑上述文件，也不要把备份 EXE 手工复制回去。

## 助手被强制中断后的人工恢复（已接受的剩余风险）

preview.40 的旧助手在两次改名之间被强制终止或断电，可能留下主 EXE 缺失；它没有无人干预重启恢复助手的机制。这个首次升级限制没有被新候选消除。

1. 等待当前更新进程结束；如刚断电，先正常启动 Windows。不要同时启动多个恢复助手。
2. 如果主 EXE 缺失或原快捷方式提示找不到文件，在原安装目录打开 `.mhx-updates`，按时间找到本次更新的 `tx-...` 文件夹。可用记事本只读查看 plan.json，核对版本、Target、Backup、DataRoot、ConfigBackup；不要编辑。
3. **直接双击该文件夹里的 `updater.exe`**（不要加参数、不要使用命令行）。出现“MHX Studio 恢复”窗口后点“是”。旧助手只在目标 EXE 缺失时，从经 SHA 校验的旧 EXE 及配置/SQLite 快照恢复并重启；备份保留。
4. 核对恢复后的 preview.40 版本、配置位置及绑定/数据。若原来使用自定义数据目录，旧助手虽然按计划恢复原数据，但自动启动可能使用默认目录；请关闭窗口，使用原来带自定义目录的启动快捷方式重新打开，不要新建配置或复制数据库。该自定义目录 GUI 场景未在本轮测试。
5. **若目标 EXE 仍在、恢复窗口拒绝覆盖、备份校验失败或程序仍不能启动，停止操作并保留安装目录与数据目录以便支持诊断。不要删除现有 EXE 来强行恢复，不要手动下载替换文件。**

上述 GUI 恢复适用于旧 EXE 已备份、目标缺失的已验证状态；不承诺覆盖所有断电/磁盘故障。配置快照有旧助手固有的 64 MiB 总容量等限制，备份失败会拒绝安装，而不是清空数据。
