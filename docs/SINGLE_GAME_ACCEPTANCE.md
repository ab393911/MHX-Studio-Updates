# 单台游戏启动与指定角色：历史阶段说明

用户已补充preview.19绑定并按包名打开到公告实机通过；自动登录仍未完整验收。当前集中版范围以HANDOFF_ACCEPTANCE_20261029.md为准。

本轮仅新增单台启动游戏、识别登录页、进入一个指定角色并停留。五台游戏自动化、任务、战斗、创建角色、切换区服均未开发。本机所选区服保持原样，不自动点击服务器。

## 复用与新增

直接复用preview.17的雷电动态发现/启动、ADB实例+Android ID+boot ID身份校验、960×540截图、页面双特征及角色选中/昵称模板、随机点位/延迟、停止、重试、有限缓存、异常诊断、在线更新和配置快照回滚。

V3.3已由用户人工逐步触发ADB验证游戏内“设置→返回登录→选择角色→踏入仙途→重新进入游戏”，新状态流程沿用该路径及下面坐标，不重设计路径。人工点击通过不是无人干预自动化通过。

新增internal/gameapp只通过已核验ADB枚举实际Android启动入口，不预设游戏包名；不唯一确认时弹出GUI选择，只有用户明确确认才保存绑定。同一实例下次自动恢复，重新核验安装入口和Android身份。游戏在前台不重复启动；后台已运行则用正常启动Intent恢复前台，未使用force-stop或am -S。启动后检查实际前台包名。每次截图和点击前均继续核验游戏在前台，外部弹窗或切到其他应用时停止。

新增单角色状态机复用现有标定格式。每次关键动作前检查实际截图、短随机等待后再核验；动作后连续两帧确认目标页面。选中目标角色前不点进入按钮。角色昵称模板无法核验时显示“身份未核验”，不能记录完全成功。正常截图仅存在有限内存缓存，未知/失败页面持久化诊断最多20组；手动停止不保存异常截图。

## 用户测试顺序（无需命令）

1. 在preview.17点击“一键检查更新”，等待自动重启。确认版本、成功提示、D:\LDPlayer14、原设置/角色/标定以及24实例、运行5、ADB5保留。模拟器单台及五台启动继续按原按钮使用。
2. 先只选择一台ADB已验证的模拟器，点击“发现/绑定游戏”。如果不能只凭包名判断，先在该模拟器里手动打开一次轻享，再点“重新读取已打开的游戏”，选择标记[当前前台]的入口并确认。这个首次绑定步骤只确认目标，不试启动其它应用。绑定成功后下次不用重复。
3. **优先验收阶段A**：回到模拟器桌面，点“仅启动游戏”。应自动打开已绑定游戏并报告前台核验。再次点击，游戏在前台时不应强制重启。若只在后台运行，应恢复到前台。软件不会安装缺失游戏。
4. 阶段A通过后再测试登录。选择目标角色1～5，点“标定指引”。现有真实标定直接复用；缺少的页面需在对应实际画面点击“截图并框选标定”，框选两处稳定特征和按钮内部。角色选中标定须包含目标行高亮/昵称；游戏内标定须包含该角色昵称，避开动画和计时数字。动画页未出现可略过。没有真实模板不能自动识别，更不能靠坐标假装成功。
5. 在公告/登录/角色页点击“启动游戏并进入角色”。观察“当前模拟器、目标角色、页面、步骤”。应只进入所选角色并停留游戏内。已经在目标角色内则直接验证，不重启。处于其他已标定角色内时，经已知菜单/设置/返回登录路径再进入目标角色；遇缺失标定或未知确认框则停止。
6. 操作中点击“停止”，应结束等待且不开始下一次点击。未知页面或错误角色不得继续点进入。失败后可点“查看异常截图”查看本机PNG及JSON；不要上传账号密码。
7. 反馈阶段A结果与页面截图，完成单台真实验收后再扩展五台。单台真实验证前不继续任务或战斗。

## 技术依据

Android官方ADB工具说明：https://developer.android.com/tools/adb
Android包管理器入口查询实现：https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-8.1.0_r68/services/core/java/com/android/server/pm/PackageManagerShellCommand.java

不依赖Python、Java、外部OCR、用户命令行或下载SDK。仅使用雷电自带ADB。没有假设特定游戏包名、端口或实例编号。

窗口适配：主程序按Windows实际工作区居中并缩小外框，日志随客户区调整；“停止”放在主窗口较靠左的固定位置。标定截图保持960×540原比例，标定和游戏选择窗口也移入工作区。原页面模板与雷电/更新实现保持不变。
