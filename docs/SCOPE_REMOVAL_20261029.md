- preview.21 schema 1 → 本分支schema 2，整次迁移在BEGIN IMMEDIATE事务中，DDL、计划、停用标记、原始配置归档及版本一起提交；任意错误回滚全部。
- tasks新增enabled字段。旧tower/daily/arena只改enabled=0，不改phase、actor、module、state、attempt、evidence、reason、updated，不伪造完成或条件跳过。
- plan_scope_history保存旧config原字节；当前config保留未知字段。phase_layout与historical_batches记下历史编号布局，保留阶段存在空洞；旧战令10不会变成旧锁灵塔7，下一角色11仍是11。

- Next、SetTask、GroupComplete、恢复和工作台均只读取启用任务。每次推进核对实际任务身份/模块/编号/启用状态及完整性，缺行、错身份、未知模块暂停。仅有停用任务的旧计划归档，不报告实际游戏成功。

独立更新器先备份、退出旧程序再替换；新程序校验备份后迁移既有数据库，迁移成功才写启动健康回执。失败不确认，由原更新器回滚EXE与配置/数据库快照。SHA、配置、WAL/SHM、失败文件隔离及凭证目录策略不变。

Windows原生CI下载并固定校验已发布19与21：19至本分支候选直接单击升级；21用原EXE GUI生成旧11阶段计划与订单，升级后核对8阶段范围、旧编号和订单。候选服务是临时可信HTTPS回环服务器，仅CI证书库临时信任，不修改生产TLS、发行资产或生产清单。最终批准发布前仍须重跑正式GitHub候选地址及19直升验证。

- v1→v2全部任务原字段不变；6种任务状态、原配置及未知字段、订单/额度/确认与未决流水/消息队列/凭证不变；重复打开幂等。

- 停用任务只读、不能复活；停用活动不打开跨日边界；追加批次不复建旧任务。
- 原v1数据库更新快照→迁移→模拟失败→还原原DB字节，保留财物与凭证、隔离失败DB，再迁移可用。

## 风险与未验收

- schema 2不能直接交给旧preview.21读取；正常降回必须用更新器保留的原EXE及原DB快照。不会要求用户手工替换。
- 未知/乱序的旧模块、损坏或缺失任务会阻止迁移，不自动猜映射或宣称完成。原DB保留供诊断。
- 大型历史数据库的健康检查耗时仍受更新超时限制；超时按失败回滚，不忽略完整性检查。
- 新执行器、真实战斗、银锭发送均未新增。本分支和真实故障回滚未获用户实机验收，Windows CI与接口替身不代表真实雷电游戏成功。
