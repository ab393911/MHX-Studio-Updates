# MHX Studio 测试步骤（无需 Python 或命令行）

## 先测试更新

1. 将压缩包解压到一个新的、可写的文件夹，双击 **MHXStudio.exe**。保留原 V3.3/V3.4 文件夹。
2. 窗口应显示版本号、雷电目录、实例选择、运行日志和“一键检查并更新”按钮。若未出现窗口，把现象和截图反馈给开发端。
3. 点击“一键检查并更新”。没有更高版本时，应显示本地版本、清单版本和无需更新；网络失败应显示错误，当前 EXE 不变。
4. 以后开发端发布更高版本时，再点同一按钮。弹窗会给出版本和备份替换说明，**只有你确认后才安装**。下载、校验后程序自动重启。
5. 点“检查未完成更新”查看事务结果。成功应是 committed；新程序启动失败应是 rolled_back。旧 EXE 保存在程序目录的 .mhx-backups 中，每次备份文件名不同，不会删除或覆盖旧备份。
6. 新版本使用同一数据目录，设置、标定和未知配置字段保留。配置损坏时程序会停止并保留原文件，不会用默认配置覆盖它。

如果更新失败且主程序没有恢复，不要删除 .mhx-updates 或 .mhx-backups。可以双击本次事务目录中的 updater.exe，通过其恢复入口恢复缺失的主程序；已有 EXE 不会被这一恢复入口覆盖。若出现 recovery_required，请保留目录交给开发端排查。

GitHub 在你的网络环境中能否直接访问，仍需这一步实测。程序已支持可配置的 HTTPS 清单地址；目前没有声称部署了国内镜像，也没有填写虚假镜像或示例哈希。

## 再测试单台雷电

1. 雷电设为 **960×540 横屏**，开启 ADB 本地连接，先只用一个实例测试；窗口不要最小化，也不要让旧脚本同时控制它。
2. 在 MHX Studio 点“选择雷电程序”，选择安装目录里的 **ldconsole.exe 或 dnconsole.exe**，再点“检测实例”。程序应列出所有实例及雷电返回的原始编号；已运行实例显示通过身份验证的 ADB 设备。
3. 从实例下拉框选择要测的一台，选择职业，再点“绑定五个同职业角色”。此处是人工绑定，不代表程序已经自动识别职业。
4. 从“标定页面”选择对应页面，让游戏停在该页面，点“截图并框选标定”。在图上依次框出：第一处稳定特征、第二处独立特征、实际可点按钮范围，最后点保存。框选时避开动画、计时数字、遮挡物。
5. 需要标定的实际页面：公告页的黄色踏入仙途；角色列表的公共区域和踏入仙途；菜单展开页的设置按钮；设置页的返回登录。若实际还存在大树登录页或返回登录确认弹窗，也要分别标定。
6. 对五个角色分别标定“第 N 个已选中”和“游戏主界面第 N 个角色”。选中页特征必须能区别该角色，例如昵称与对应行的高亮；游戏内特征应包含该角色独有昵称。第三框分别是该角色行和菜单按钮。不同角色特征相同会被拒绝。
7. 先点“只检查当前识别”，确认日志与实际页面一致。页面未识别时不点击。
8. 点“单机闭环：5角色”。程序应按 1→2→3→4→5 选择角色，核对选中和进入后的身份，执行菜单→设置→返回登录。最终返回已识别的登录页；只有五个角色全部通过才记录单机验证。
9. 在未知页面或遮挡弹窗下测试：程序应停止或在设定次数内等待重试，不能继续盲点。重试次数可设置为 0～20，表示首次尝试之外的额外次数。

正常帧仅在内存保留，每台最多2帧、总计32 MiB。只有异常才将当前截图和错误信息写到本机 diagnostics，最多20组，不自动上传。标定只保存少量灰度特征与按钮范围。

## 最后测试五开

1. 对五台实例分别完成单机五角色闭环。修改标定、设备身份或职业后，旧验证失效。
2. 选择本轮五台连续的雷电原始编号，在“五开首编号”填本组首号。例如首号6，目标是6～10；不固定为1～5，也不会把编号缺口压缩成另一组。
3. 人工绑定阵容为合欢、天音、青云、鬼王、鬼王，每台内部五个角色同职业。
4. 点“五开闭环测试”。未完成单机验证、编号缺失、设备身份冲突或职业绑定不符，都应拒绝开始。
5. 任一台失败时，整组取消后续动作。点击“停止”也会取消后续动作。已发出的单次 ADB 点击无法撤销，关键状态仍需反馈核对。

本版本不做战斗，也不会自动换区。任务模型要求当前区服、当前组每台五个角色的全部任务都标为 verified_complete 才可解锁换区；pending、failed、skipped 都不算完成。没有战斗/任务完成证据时该闸门保持关闭。

## 完成状态怎么判断

- 能下载、能编译，不等于已在 Windows 运行。
- WINDOWS_AUTOMATED_TESTS.json 证明 GitHub Windows 环境里的 GUI/更新测试结果，不证明雷电游戏流程。
- 真实 Windows + 雷电 + 游戏的识别、点击、角色身份和网络可达性，需要按上面步骤验收；在这些结果回来前，不将其标为实机成功。
