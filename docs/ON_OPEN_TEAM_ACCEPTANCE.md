# 打开软件自动启动与组队测试（开发中）

## 交付范围

本分支接通保存方案→重新打开MHX→倒计时→按指定五台启动→实际ADB/设备/游戏绑定核验→登录同区同槽位→最后五台复核。可选择在登录后继续执行组队及八星准备测试。未发布、不改更新通道。首次配置仍通过GUI完成，之后无需每次重新选择或点击启动。没有设置Windows开机启动项。

已有配置不会被默认启用自动动作：不能猜测用户这次选择哪五台、哪个角色、谁当队长。首次保存后才生效。

## 图形设置

1. 五开工作台勾选任意五台，打开“五台同槽登录准备”。确认区服和共同角色槽位；当前内置区服文字为一梦诛仙。
2. 勾选“打开软件后自动启动本组并登录”，点击“保存启动方案”。保存的是实例编号、已绑定Android设备身份和游戏包名，下一次启动重新发现ADB序列号和boot ID。
3. 下次手动双击MHX后自动执行；倒计时和执行中均可点“停止”。停止只取消本次，关闭复选框并保存可停用后续自动运行。
4. “登录后继续组队及八星准备（测试）”单独勾选，并明确选择队长。此项要求已保存五开计划，会读取本次角色列表的五个昵称、按绑定职业核验图标，并核验昵称；不沿用旧报告当作当前身份。

缺少游戏绑定、独立角色昵称标定、已保存实例不存在、Android身份变更、计划当前组不一致、任务待核查、订单额度锁定或买家消息待核查时停止。自动流程失败后不会在定时器中反复重启。

## 登录补全

角色列表本身没有区服文字。如果本次启动直接进入角色列表，先连续确认角色页面，再使用截图144左上返回箭头退到大树登录页；连续核验目标区服后继续。公告直接进角色列表也走此路径。

已在目标角色内时不强制退出制造区服证据。本次没有区服依据时仍报告不完整，不开始组队。该限制需要后续从真实游戏补充可读取区服的界面或其它可靠依据。

## 真实组队执行器

- 全组首先重新验证当前游戏角色昵称标定；选择的五台必须属于同服同槽位，职业为1合欢、1天音、1青云、2鬼王。
- 队长进入队伍，核对实际队伍；已经正确组队时不重发邀请。
- 未成队时进入固定队，核对本次五个昵称、队长及五人在线状态，核对离线托管状态后发起组队；只确认“创建队伍并邀请固定队成员”的弹窗。
- 队员识别截图103的邀请铃铛和“队伍”字形，忽略动态通知计数与背景；打开邀请列表后核对邀请队长，等待倒计时结束再接受。
- 五台分别读取实际队伍页的五个名字、队长标记，不能用固定队预设代表队伍已经5/5。全部核验后逐个返回主界面。
- 每次动作前随机短延迟后重新截图检查，动作后连续确认实际页面；响应不明不重复提交邀请/接受。用户停止后不开始新点击。
- 若本地计划正在team阶段，五个任务先在单个事务中获取执行状态；全部验证后才记录对应组队完成。失败/不明保留待核查；其它保留模块并未因此完成。

## 文字识别与截图

使用Windows自带WinRT OCR，通过隐藏的固定桥接进程调用，不要求用户输入命令、安装Python或上传截图到服务。正常截图在内存/管道中传递，不保存临时图片。OCR请求有大小、行数、坐标和超时限制；截图缓存仍有限，异常才持久保存。

组队昵称要求本机存在中文识别语言。无中文能力、文字不唯一、未知页面、固定队不对应本次角色时暂停，不猜测、不自动安装系统组件。Windows自动测试中生成的英文文字OCR不等于真实游戏中文识别通过。

## 测试与限制

自动化覆盖保存/停用方案、未知配置保留、动态五台、冷启动、ADB绑定、打开游戏、从角色页回退核验区服、目标角色、倒计时停止、错设备不执行、更新健康检查和提交前不自动运行，以及五人任务事务失败回滚。

组队执行器的流程测试使用模拟设备和模拟OCR结果；WinRT桥接另用Windows生成文字实测。真实雷电/游戏组队尚未验收，不能称已通过。最终Windows GUI、19直接升级、21迁移和故障回滚结果以提交对应Actions报告为准。

## 八星准备执行器（未实机验收）

组队后仅在持久计划当前阶段为eight_star且同服同槽时执行。已完成的单实例记录保持不变，不重复消耗；待核查阻止自动恢复。五台分别核验打符8★、四行、覆盖开启、强化关闭，读取材料并只提交一次，随后核验材料各减一及四项属性增益值。截图中的分数不作为剩余次数。资源不足经两帧核验后跳过。

按绑定职业选择目标幻形；已经8★冻结时不重复。缺卡时只进入商行购买，核验目标、8★、数量1、铜钱图形及余额，不使用获取途径默认3★卡作为购买依据。购买只提交一次，以持有数量增加核验；响应不明不重买。幻形卡下数字的资源含义未明确，不能用它推算余额；核验实际消耗说明后仅点击一次，以连续冻结结果或明确不足提示判定。没有已识别取消按钮的补充窗口停止，不确认补充消费。

数字字段使用内存局部放大OCR，万字缩写保留区间，不能当作精确余额。正常截图不落盘。`profiles/eight-last.json`仅为历史诊断，不用作下次点击许可。自动测试使用模拟设备/OCR，Windows生成数字识别另测，均不代表真实游戏验收。

**本分支尚未接通聚福激活、据点战斗、交易行、游戏余额数字读取、战令及真实银锭赠送/聊天执行。**这些仍需执行代码与测试，不只是等待用户实机验收。当前也不会自动切角色、换区或换批。

所有后续交付继续使用软件内一键更新，保留配置、标定和SQLite订单数据；不让用户手动下载或替换EXE。
