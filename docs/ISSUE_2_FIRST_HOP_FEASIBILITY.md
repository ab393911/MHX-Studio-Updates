# preview.40 不可修改旧助手的首跳恢复研究

2026-11-02，上海时间。当前要求：继续通过已安装 preview.40 的“检查更新”首跳，不能先修改旧助手，不能把新候选运行后的能力当作旧首跳能力；不发布、不修改稳定清单、不操作用户配置或 SQLite。

## 旧版执行时序与边界

固定原包 SHA-256：`e58eaef41b4e37361f79cc500872bc89f1e7ebe37d810785740b294eb397daa2`。
发布源码：`bfc5e2f0336ede93e963d364cac21fb1a2f15a43`。

原版 `onlineUpdate` 下载包并校验，随后复制当前 EXE 为 `updater.exe`，要求助手文件 SHA 与原版完全相同，启动旧助手，再退出父程序。它没有下载/启动新监督器的入口。清单提供版本、HTTPS 包地址及哈希等元数据，不提供执行安装前脚本或替换助手的受支持能力。

旧助手：等待父进程退出 → 再校验原包和候选 → 备份配置/SQLite → 旧 EXE 移入备份 → 候选移入目标 → 启动候选 → 健康检查。

因此两次改名之间强制终止旧助手时，新候选从未执行；任何候选内的监督器、原子替换、启动恢复注册均尚未生效。

## 方案可实施性

| 方案 | 对未来更新的作用 | 是否可仅由现有 preview.40 更新按钮保护本次首跳 |
| --- | --- | --- |
| Windows 原子替换（例如 ReplaceFileW） | 可以在采用该调用的更新器中减少目标缺失窗口；仍须分别验证原子提交后健康失败与数据回滚 | 否。已运行旧助手仍执行两次改名，服务器元数据无法更换其调用 |
| 外部恢复监督进程 | 若在旧助手替换前已运行，可以等待旧助手异常退出、校验事务/备份并启动受控恢复 | 有前置条件。旧版没有部署/启动该进程的钩子；新候选启动监督器太晚 |
| Windows 启动恢复（服务/任务/启动器） | 预先部署后可在重启或再次启动时处理未完成事务 | 否，当前版本没有该预置组件。候选注册动作发生在缺口之后；仅依赖主 EXE 启动也不能处理主 EXE 缺失 |
| 先通过相同旧助手升级“桥接版” | 桥接版成功启动后可为后续更新安装加固机制 | 不能免除首次桥接本身仍使用旧助手的风险 |

可实施的带条件方案是预先部署独立恢复组件，然后继续复用原下载、备份、SHA 校验、健康检查与回滚系统。它需要明确允许且实际完成的首次部署/恢复入口验收，不是现有软件按钮已经具备的能力。本轮不在用户电脑注册服务、任务或启动项。

## 新增 Windows 实证

新增诊断工具 `tools/firsthopverify`，不是用户安装器，不随业务版本分发。

- 下载并核验真正发布的 preview.40；原助手磁盘文件始终保持固定 SHA。
- 使用 Windows 调试 API 与线程硬件断点，观察原助手的原生重命名调用，在成功返回后、旧调用方继续执行前用 `TerminateProcess` 终止原进程。
- 不是运行新候选的 Installer 注入函数来替代旧包；不修改旧包代码字节。
- 对照条件：无监督器，以及在故障前已启动并握手确认就绪的监督器。后者的首次部署由 CI 测试工具提供，明确不算 preview.40 自己部署。
- 所有 EXE、配置及 SQLite/订单哨兵位于一次性 Windows 临时目录，不接触用户数据。
- 每次探针 150 秒总超时。首轮 Win32 调用层探针未命中故障点，不算通过；只做一次底层原生调用修正，不无限重跑。

Windows 工作流执行成功表示以上正反对照均得到有效证据，**不代表首跳发布条件通过**。机器报告 `first_hop_solved_under_existing_constraints=false`、`publication_ready=false`。

首轮运行 `41445280254` 未命中 Win32 层故障点，不计为有效验证；只修正一次改为观察底层原生调用，第二轮 `41446573082` 完成测试。此后停止重跑。

## 发布决策

除非验证并满足首跳前置部署条件，否则不得把预置监督器的成功当作现有一键首跳已修复。原子替换和启动恢复也不能通过“仅改候选代码”倒流到旧助手执行之前。

未创建发布、未修改 `updates/preview.json`，未操作用户配置、SQLite 或模拟器数据。
