## 代码发现与修复

实际组件为Go原生Win32/GDI，无Tkinter或Pillow。两个窗口共用calibration.paint。旧版使用未检查返回值的StretchDIBits，先以WS_VISIBLE创建窗口、随后才绑定HWND/绘制状态；共享窗口类的默认WM_ERASEBKGND可擦白图像，而图片代码仅处理WM_PAINT。旧自动化使用PrintWindow，会主动要求绘制，不能证明用户实际看到的桌面正常。

新版先创建并持有原生顶向下32位DIB位图，填充不透明BGRX；绑定窗口、标签及图像后显示并显式请求首次绘制。两窗口复用同一绘制函数，处理WM_PAINT、提供DC的WM_ERASEBKGND/WM_PRINTCLIENT、窗口尺寸及DPI消息；BitBlt失败再尝试经返回值检查的StretchDIBits。销毁时释放GDI对象。绘制失败显示原因并阻止保存，保留旧标定。

旧版已持有Go图像/切片，不能声称已证明是垃圾回收释放引用。新原生所有权减少驱动与临时存储不确定性；本次修复不证明用户机器的具体DPI/显卡触发链。WM_ERASEBKGND是重绘故障注入；本次CI旧版正常恢复，未复现用户白屏，不能冒称已证实原设备根因。

截图解码/识别与窗口显示分离。GUI白屏不会自动解释73.246/64.424的识别均值；本轮不承诺修复真实主界面识别。
