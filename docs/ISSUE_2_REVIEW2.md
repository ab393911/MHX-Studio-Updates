## 发现并修复的问题

1. **取消后异步结果仍生效**：上一版工作线程在界面回调处理前无条件取消自己的 context，UI 回调也没有检查用户取消。用户停止/关闭窗口后，已排队的绑定保存或继续启动可能执行。现在 context 保留到界面完成处理，动作回调检查取消状态；停止清除内部继续动作，显式排队的更新等用户请求优先。取消、关闭选择窗后不会继续保存/启动。
2. **编号一致不代表仍是同一目标**：异步结果原先只检查编号/列表位置。新增完整快照，包含控制台与 ADB 路径、实例编号、PID、窗口、serial、Android ID、boot ID、目标角色。写入结果及继续动作两个时刻都核对快照；继续动作仅消费一次。用户在等待时切换实例/角色，或设备身份变化，不再把旧请求应用到新目标。旧的错误桌面绑定会进入明确重新选择路径，不再反复尝试启动桌面。
3. **恢复后可能使用旧截图点击**：连接验证中的自动恢复可能耗时，成功后继续点击会使用恢复前的图像/前台依据。新增每次动作共享的恢复屏障：只读截图/识别可自动恢复；点击、滑动或启动命令的验证阶段经历掉线时，恢复后终止这一次动作，须重新检查页面。前台读取的 activity/window 备用查询不能抹掉已发生的掉线；不会暗中重放原点击。
4. **身份校验链不完整**：明确 boot 查询掉线原先可能降级成无 boot 的匹配；恢复时也可能只依赖可克隆的 Android ID。现在明确掉线时不发布“已验证”映射；缺少 boot 身份时拒绝自动恢复动作。重新核验编号侧身份后，再复核 serial 侧身份与窗口，拒绝核验过程中的实例重启/窗口变化。旧设备无 boot 但正常在线时的原有检查路径保留。
5. **动作结果不确定不能冒称成功**：ADB 可能退出码为 0、stdout 却报告 offline。点击/滑动/启动命令已发出后的传输失败或明确错误输出统一报告“结果未确认”，不自动重连重放。取消后的命令在统一调用入口被拦截，防止继续交给 Runner。

## 剩余风险与实机验收

- Linux 测试及 Windows 交叉编译不能代替 Windows 消息队列、实际雷电控制台/ADB 行为验收。需要在用户保留的独立测试环境中重复“启动/绑定→立即停止/关闭”、切换实例/角色、offline 恢复及恢复过程中弹窗的场景。
