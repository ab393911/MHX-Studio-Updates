# 雷电检测与启动修复

旧代码只接受7列`list2`，而雷电9/14官方接口可返回10列（追加宽、高、DPI）；此外没有启动自动扫描、只搜索少量固定安装路径，且任何一个实例ADB绑定失败都会丢弃整次发现结果。

当前流程：从明确选择的安装位置、运行进程完整路径、Windows安装记录及各本地盘常用目录寻找控制台；保留安装边界，使用雷电原始编号。先展示实例，再逐台核对ADB。未运行、安卓启动中、ADB未就绪和ADB已验证分别呈现。

克隆的Android ID不是唯一设备证明，匹配时额外使用内核boot ID。ADB的多个串号若指向相同启动身份可选择一个，两个实例的身份仍重复时拒绝点击。每次点击/截图前继续核对实例PID、窗口绑定与设备身份；不使用固定端口推测绑定。

启动前先检查全部指定编号存在，只发送`launch --index`，跳过已运行实例，并轮询`list2`确认安卓启动。没有使用创建、复制、删除、重置、修改ADB设置或关闭模拟器的命令。取消或启动失败保留已经打开的实例。

参考雷电官方[ldconsole开发者说明](https://help.ldmnq.com/docs/LDPlayer-ming-ling-hang-kai-fa-zhe-shi-yong-shuo-ming)：7列基础字段及追加显示字段、`launch --index`、按实例调用ADB。实现与CI测试替身均以文档为接口依据。

单元测试验证解析、异常隔离、克隆及别名、启动范围、缺失编号、超时和取消。Windows自动测试使用实际MHX GUI和独立CLI测试替身进程，尚不证明雷电或游戏实机成功。测试替身不放入用户安装包。
