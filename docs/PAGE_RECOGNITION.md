# 页面识别与GUI诊断（第一阶段）

此实现位于未发布候选中，现有issue2.1不会自动获得新GUI；本轮不发布、不要求替换EXE。

## 用户操作

- 在已运行的正确实例上点击“一键识别诊断”。不启动游戏、不点击游戏，也不自动修改规则。窗口可直接查看/复制报告、在软件内置窗口查看原始960×540图像、通过标准保存对话框导出ZIP。
- 取图前后核对实例身份。取不到可靠截图、尺寸不符或规则无效会显示具体失败，不伪造截图或分数。停止/切实例后的旧回调不会打开过期报告。
- 报告包含规则来源、算法版本、规则修订号、原始/有效规则哈希、实例/ADB身份、每框误差与超差点数、模板和当前灰度采样。新标定还记录原始像素哈希；旧标定没有原图哈希，不能补造。
- ZIP仅包含截图、报告、摘要及本次实际读取的规则快照；不导出配置、SQLite、订单或更新日志。截图可能含游戏信息，分享前由用户确认。手工点击诊断才保存正常画面；本轮不增加定时截图频率。
- “页面规则”窗口选择“本实例”或“公共页面”，可预览/编辑JSON、导入导出、从默认历史目录选择旧版本预览，再明确确认保存。恢复结构有效的历史规则后仍需实时诊断，不宣称实机一定匹配。
- 输入页面ID、名称、按钮ID及2～8个特征数量可实时框选。最后一框始终为按钮区域。保存前校验、保存旧文件、原子写入、重新读取并用本次标定原图自检。自检不是跨帧或实机稳定性验收。

## 统一接口与安全边界

复用internal/automation的Profile、Page、Anchor及原采样算法。Score返回所有特征分数；Match/Require、原登录Recognize与新增DetectRules调用相同Score。DetectRules只在指定页面ID集合唯一匹配时确认，冲突/未知返回RecognitionFailure及实际分数。现有登录保留选中槽位/通用页面的既有重叠判定，不把新自定义页面自动加入已验证的登录状态机。

识别器不执行点击或重试。执行器继续使用现有有限Retries/StateTimeout以及每次动作前的新鲜画面和身份保护；不确定时不点击，动作结果不明不重放。RecognitionFailure穿过现有包装错误，异常记录能保存各特征结果。职业识别、数字OCR和业务状态机保持其既有专用判断，不用页面灰度特征冒充职业或金额证据。

## 外部规则格式与优先级

继续读取schema=1的现有JSON。Page增加可选label、revision、button_id、feature_thresholds、min_matches、calibration_image_sha256字段；旧数据不需要迁移。

- anchors：2～8处，每处rect仍在原始960×540内，pixels仍为32×16的512个灰度采样。
- threshold：原平均绝对灰度误差上限，1～20；feature_thresholds可逐框覆盖，长度必须等于特征数。
- 每框仍要求灰度差>40的采样点不超过40。未调整旧两道门槛，不以降低要求解决间歇失败。
- min_matches省略/0表示全部特征通过；若明确配置，至少2处且不超过总数。特征通过比例不是统计概率。
- button_id引用同一Profile.buttons中的点击矩形。无按钮关联的旧页面仍兼容。
- 不自动修改已验证规则。用户明确保存后，内容变化递增修订号、原字节留存history；只变版本号不能自动造成规则修改。

加载优先级：内置候选 → profiles/shared.json → profiles/<实例>.json。公共文件仅保存规则，不包含设备或任务状态。每次新识别/新任务重新读取；已开始的任务使用自身规则快照，GUI不允许运行期间改规则。异常公共文件会安全停止，不能悄悄换回其他规则。

新增页面或移动按钮可通过GUI更新规则，无需重新发布EXE；新任务流程、状态机或算法版本仍正常改代码。未来任务传入明确页面ID，复用同一规则库，不另造平行的页面匹配系统。

## 保留与待完成

Windows原生测试使用合成画面和模拟设备；不等于真实雷电。主界面间歇失败的根因仍需用户实机诊断包。当前不做AI自学习、自动放宽阈值、远程修改规则或未授权发布。

扩展多特征规则不是旧版可读取格式；未来回滚需通过更新器恢复升级前规则快照。现有备份器已覆盖profiles下JSON，包括公共规则与历史，本轮不改更新器或SQLite结构。
